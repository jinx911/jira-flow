# Init Jira-Flow

One-command initialization of the jira-flow workflow for a project. Auto-detects tech stack, generates configuration, registers the project, and verifies dependencies.

**Trigger**: user says "init jira-flow" / "初始化 jira-flow" / `/init-jira-flow`

**Input**: `$ARGUMENTS` (optional, project path. Defaults to the current working directory)

## Workflow

```
1. Detect:   Scan project directory, identify tech stack, repo structure, database
2. MCP:      Verify atlassian-rovo connectivity, obtain cloudId
3. Generate: Create two config files
4. Register: Update projects.json
5. Dependencies: Verify skills / agents / superpowers
6. Validate: Confirm all files are present and references are correct
```

---

## 1. Detect

Determine the project root path:

```
ARGUMENTS non-empty → use specified path
ARGUMENTS empty     → use current working directory
```

Run scans in the project root directory:

```bash
# Tech stack detection
ls composer.json package.json pom.xml build.gradle go.mod Cargo.toml 2>/dev/null

# Repo structure (multi-repo detection)
find . -name .git -maxdepth 3 -type d 2>/dev/null

# Frontend detection
cat package.json 2>/dev/null | grep -E '"react"|"vue"|"angular"|"svelte"'
ls */package.json 2>/dev/null

# Database detection
grep -r "DB_" .env 2>/dev/null
grep -r "database" config/ 2>/dev/null

# Docker detection
ls docker-compose.yml Dockerfile 2>/dev/null

# Git main branch
git symbolic-ref refs/remotes/origin/HEAD 2>/dev/null
```

Inference results:

| Detected | Inferred |
|----------|----------|
| `composer.json` + `"laravel"` | backend: laravel |
| `package.json` + `"react"` | frontend: react |
| `package.json` + `"vue"` | frontend: vue |
| `pom.xml` / `build.gradle` | backend: java/spring |
| `go.mod` | backend: go |
| `.env` with `DB_CONNECTION=mysql` | database: mysql |
| `docker-compose.yml` | docker: yes |
| Subdirectory with `.git` | multi-repo architecture |

---

## 2. MCP Verification

```
Call mcp__atlassian-rovo__atlassianUserInfo
  → Success: get user info, confirm MCP is available
  → Failure: AskUserQuestion "atlassian-rovo MCP is unavailable. Please check your settings.json configuration. Continue generating config files?"

Call mcp__atlassian-rovo__getAccessibleAtlassianResources
  → Obtain cloudId
```

---

## 3. Generate

### 3a. Flow Config `~/.claude/skills/jira-flow/project-config.md`

This file is the jira-flow process-level config, one copy per jira-flow installation.

> If it already exists: read the current content, **preserve user-customized branch_naming and openspec settings**, only update cloudId and root_path.

Generated content:

```markdown
---
name: jira-flow-project-config
description: Jira-Flow process config. Project-specific info is in {root_path}/.claude/project-config.md.
---

# Jira-Flow Process Config

> This file only contains configuration for the jira-flow workflow itself.
> Project-specific info (repos, databases, test environments, etc.) is in `{root_path}/.claude/project-config.md`.
> The project config is generated by `/init-jira-flow`, or can be manually created using `project-config.example.md` as reference.

---

## Jira Configuration

cloudId: "{auto_detected_cloudId}"

## Project Path

root_path: "{detected_project_path}"

## OpenSpec

openspec:
  changes_path: "openspec/changes"
  baseline_path: "openspec/specs"

## Branch Naming

branch_naming:
  format: "{issue_key}"

## Jira Status Mapping

# transition IDs are obtained at runtime via getTransitionsForJiraIssue
```

### 3b. Project Config `{root_path}/.claude/project-config.md`

This file is the project-level config, containing full information about repos, databases, test environments, etc.

> If it already exists: **do not overwrite**; prompt the user to manually merge missing fields.

Generated based on detection results. Populate detected values using the `project-config.example.md` format. Minimal template:

```markdown
# {project_name} Project Config

> **Purpose**: shared project-level configuration for agents and skills. Consumers simply Read this file.

---

## Basic Info

root_path: "{project_path}"
tech_stack: { backend: "{backend}", frontend: "{frontend}", database: "{database}" }

## Repo Architecture

{Based on detection results: single repo or list of modules}

## Git Configuration

git:
  main_branch: "{master or main}"
  branch_naming:
    format: "{issue_key}"

## OpenSpec

openspec:
  changes_path: "openspec/changes"
  baseline_path: "openspec/specs"

## Database MCP

{Populate based on available MCP tools}

## Build Commands

build_commands:
  frontend: "{detected frontend build command}"
  backend: "{detected backend build command}"

## Migration

migration:
  steps:
    - "{detected migration command}"
```

Key fields:

| Field | Source | Required |
|-------|--------|----------|
| `root_path` | Project path | yes |
| `tech_stack` | Detection results | yes |
| `backend.main_repo` | Repo structure detection | yes |
| `frontend.repo_path` | Repo structure detection | conditional |
| `modules` | Sub-repo detection | conditional |
| `git.main_branch` | Git detection | yes |
| `databases` | User confirmation | conditional |
| `build_commands` | Tech stack inference | conditional |
| `migration` | Tech stack inference | conditional |
| `test_environments` | User input | no |
| `e2e_testing` | User input | no |
| `deploy_branch` | User input | no |
| `jira_workflow` | User input | no |

### 3c. Confirm

Before generating, display detection results via AskUserQuestion for user confirmation or correction:

```
Project path: {path}
Tech stack: backend={x}, frontend={y}, database={z}
Repo structure: {single-repo / multi-repo}
Main branch: {main/master}
cloudId: {auto_detected}

Additional config:
- Branch naming format: {format} (customizable)
- OpenSpec paths: changes={c}, baseline={b}
- Test environment available? (optional, can be added later)
- Deploy branch? (optional)
```

### 3d. settings.local.json `{root_path}/.claude/settings.local.json`

> If it already exists: **do not overwrite**; skip.

Generate a minimal permission set based on the detected tech stack:

```json
{
  "permissions": {
    "allow": [
      "Bash(git:*)",
      "Bash(ls:*)",
      "Bash(find:*)",
      "Bash(grep:*)",
      "Bash(cat:*)",
      "Bash(curl:*)",
      {if Node.js: "Bash(npm run:*)", "Bash(npm install:*)", "Bash(npx:*)", "Bash(node:*)", "Bash(pnpm:*)"}
      {if PHP: "Bash(php artisan:*)", "Bash(composer:*)"}
      {if Docker: "Bash(docker exec:*)", "Bash(docker-compose:*)"}
      {if Java: "Bash(gradle:*)", "Bash(mvn:*)"}
      {if Go: "Bash(go run:*)", "Bash(go test:*)"}
    ]
  }
}
```

## 4. Register + Create Directories

Ensure directories exist:

```bash
mkdir -p ~/.claude/configs
mkdir -p {root_path}/.claude/skills
mkdir -p {root_path}/.claude/hooks
mkdir -p {root_path}/{changes_path}
mkdir -p {root_path}/{baseline_path}
```

Update `~/.claude/configs/projects.json`:

```json
{
  "version": 1,
  "description": "Project registry — maps project paths to their configs.",
  "projects": {
    "{project_path}": {
      "name": "{name}",
      "description": "{one_line_description}"
    }
  }
}
```

If the file already exists, merge the new entry (do not delete existing entries).

## 5. Dependency Verification

Check in order, summarize missing items:

### 5a. Skills

Check that the following exist under `~/.claude/skills/`:

- `create-team` — team creation/deletion
- `delete-team` — team cleanup
- `git-ops` — Git operations

### 5b. Agents

Check that the following exist under `~/.claude/agents/`:

- `requirements-analyst.md` — requirements analysis
- `architect.md` — architecture design
- `planner.md` — task planning
- `backend-developer.md` — backend development
- `frontend-developer.md` — frontend development
- `code-reviewer.md` — code review
- `tester.md` — test verification

### 5c. Superpowers

Check that the superpowers plugin is installed (>=5.0.0):
- Check for a superpowers-related directory under `~/.claude/plugins/`
- Or check whether `~/.claude/settings.json` has superpowers in its `plugins` configuration

### 5d. MCP

- atlassian-rovo: verified in step 2
- MySQL (optional): check if a mysql MCP server is configured in settings.json
- Playwright (optional): check if a playwright MCP server is configured in settings.json

Display validation results + list of all generated file paths + missing dependency list.

---

## Notes

- Existing project config files are **not overwritten**; prompt the user to manually merge
- `project-config.md` may contain sensitive information (test environment credentials, etc.) — remind the user to add `.claude/` to `.gitignore`
- Database MCP tool names must match the names configured in the user's settings.json
- If the user has multiple projects, each run will update the `root_path` in `jira-flow/project-config.md` (re-run when switching projects)
